# M2 — specification-driven first real application profile

## Evidence from M1
The independently owned Community Picks app at `gergins/community-picks-delivery-benchmark`, draft PR #1, passed exact-source-HEAD GitHub Actions at `c939b43e89be15e3d904f92803690b8799966444` (10 HTTP/unit and one Chromium browser test), run 41629084098. It was hand-assembled. The engine M0 generated only an echo scaffold.

## Smallest missing mechanism
Add an opt-in `web-list` app profile to the existing offline generator. It emits a functional local HTML → JavaScript → JSON API → SQLite journey, unit/HTTP tests, and a Playwright browser test. The original no-profile specification continues producing the original CLI-like echo scaffold. No new workflow engine, new repository, cloud infrastructure, credentials or deployments.

## Use
```sh
python -m ade examples/web-list.json /tmp/my-picks
cd /tmp/my-picks
python -m unittest discover -s tests -p test_app.py -v
python -m app.server
```
In CI, install Playwright and Chromium to run `python -m unittest discover -s tests -p test_browser.py -v`.

## Limitations and risks
This is a **local-only benchmark** and not a general-purpose secure application generator: it lacks authentication, CSRF protection for public hosting, rate controls, migrations, production infrastructure, remote GitHub repository provisioning, and independent security/a11y review. The generator refuses to overwrite any existing target. Repository promotion and merging require explicit approval.

## Acceptance
- Existing M0 tests remain successful.
- New profile is deterministic; invalid profile refused; HTML title escaped.
- Generated HTTP/data behavior passes and SQLite survives separate connections.
- Generated Chromium browser can add an item, observe persisted API state and reload.
- Exact current PR source SHA is checked by CI; logs and result linked to PR.
